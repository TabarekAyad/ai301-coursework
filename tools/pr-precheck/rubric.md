# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| `plan-fidelity` | The diff's changed files and the nature of each change read against the plan's in-scope/not-in-scope boundary and any `## Deviations` notes; the description's fidelity claims (e.g., "implements the plan exactly", "no changes beyond it") read against the diff | Every file and every change in the diff falls inside the plan's stated boundary or is explicitly covered by a deviation note in `plan.md`; the description does not claim more or less than the diff actually delivers. An honestly disclosed shortfall recorded in both `plan.md`'s Deviations section and the description passes: the disclosure re-ties the mismatch | required |
| `test-decisive` | The test-evidence section's before/after runs read against the plan's test plan and the repro's original steps; the repo's own required checks (unit tests, lint, typecheck, integration) read against the test evidence | The test evidence re-runs the specific scenario the plan's test plan named — not just a control or an adjacent path that was already working — and shows a before state and an after state by any means: pasted terminal output, annotated output, or a clear statement of the before and after values. Evidence that only narrates "the fix works", "tested locally", or "verified on my machine" without naming specific before and after outcomes for the plan's own scenario fails. The repo's required checks appear in the evidence with their outcome (passing, failing, or explicitly inapplicable); raw pasted output from checks is not required, but a bare "checks pass" with no stated outcome context fails | required |
| `diff-reviewable` | The unified diff and the commit list scanned for debris and unrelated changes | The diff contains no debug prints, no dead or commented-out code blocks, no formatting-only hunks unrelated to the fix, and no changes to files the plan never named and no deviation note covers; commit messages are not drafts (e.g., "wip", "fix", "temp"). The fix itself must be directly visible without hunting through unrelated changes | required |
| `standards-met` | The repo-facts block's (or live repo's) PR template required sections read against the description's filled content; the stated AI-use disclosure policy read against the description | Every required template section contains real content (not a placeholder, not blank, not "N/A" where the template asks for substance); if the repo's stated policy requires AI-use disclosure, the description includes it. A section filled with a single honest "N/A — no API change" passes; a required section left blank or with the template's own placeholder text fails | required |

## Verdict rule

Accept if every required check passes. Reject if any required check fails or is unclear. Unclear counts as fail: a PR whose evidence cannot be verified from the package is not ready to submit. Preferred checks (none currently defined) never change the verdict.
